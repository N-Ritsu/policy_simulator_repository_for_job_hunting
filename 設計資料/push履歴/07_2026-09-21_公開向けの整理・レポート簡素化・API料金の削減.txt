07 公開向けの整理・レポート簡素化・API料金の削減
==================================================

■ 基本情報
- コミット: 44b0bfc
- 日付: 2026-09-21
- メッセージ: Lock to gpt-5.6-luna, hide dev output, slim the report and prompts to cut API cost

■ 概要
ゲームを将来公開することを前提に、次の4つをまとめてpushした。
 (A) 使うAIをgpt-5.6-lunaに固定し、プロバイダー・モデル選択とAPIキー入力欄を廃止。
     開発者向けの表示は、サーバー側の設定(DEV_MODE)でだけ出す。
 (B) 画面の並び順を変更。
 (C) 政策実行後のレポートを簡素化(出力の削減)。
 (D) 影響の見出し(description)を短くし、入力プロンプトを整理。
結果として、実測で1ターンあたりのAPI料金が約6割減った。

■ 変更内容
(A) luna固定・開発者表示の分離
1. APIキーの参照
   - これまで、.env のキーではなく、シェルの環境変数(~/.bashrc の export)のキーが使われていた
     (load_dotenv() は既存の環境変数を上書きしないため)。load_dotenv(override=True) にして、
     .env を優先するようにした。
2. 選択・入力欄の廃止
   - サイドバーのプロバイダー選択・モデル選択・APIキー入力欄を削除。モードの選択と開始ボタンだけが残る。
   - モデルは openai_client.DEFAULT_MODEL(gpt-5.6-luna)に固定。プロンプト・難易度の調整と費用の見積もりは
     すべてこのモデルで行っているため。Gemini・Claudeのクライアントコードは残してあるが、アプリからは使わない。
3. 開発者専用の表示(.env に DEV_MODE=1 を書いたときだけ出る)
   - 直近のAI応答(生JSON・所要時間・入出力トークン数)、生成中の途中経過のJSON、
     プロバイダー・モデル名、詳細なエラー文。
   - プレイヤーには、経過時間だけの進捗表示と、「AIの応答を取得できませんでした。しばらくしてから…」という
     一般的なエラー文だけを見せる(APIの内部メッセージ・残高不足などを見せないため)。
   - 切り替えは、URLパラメータではなく、サーバー側の環境変数(.env)だけで行う。
4. .env.example を復元し、OPENAI_API_KEY と DEV_MODE だけに更新した。

(B) 画面の並び順
- 「政策を実行して1年進める」→「勝利条件 / 敗北条件」→「現在の社会指標」の順に変更。

(C) レポートの簡素化
1. 出力項目のうち、「政策の内容と実施過程・影響」(policy_details)、「抵抗と副作用」
   (resistance_and_side_effects)、「総括」(overall_review)を廃止。「背景と影響」(era_background)と
   「諸外国の反応」(foreign_reactions)だけを残した。
   実測(旧形式の10ターン)では、この3項目が出力の文字数の約31%を占めていた。
2. 総括を出さなくなったので、過去の政策の履歴は政策文だけを持つ。過去の政策の効果は、
   AIに渡す「進行中の効果」の一覧(影響の見出し・大きさ・ピーク年)から分かる。
3. 出来事ログの政策の行は、総括の文が付かなくなった。

(D) description の短縮とプロンプトの整理
1. 各影響の description(「この影響の内容(1文)」、平均52文字)を、「影響の見出し(20文字以内)」に変更。
   計算には使わず、翌年以降のAIに渡す「進行中の効果」の見出しにだけ使われる。
2. 入力プロンプトの整理(内容は変えず、重複だけを削る)
   - スキーマ内の説明を短い要点にし、詳しい説明はシステムプロンプトに一本化。
   - 「初年度は0」の説明が3か所にあったのを1か所に。レポートの書き方の指示を1つにまとめた。
   - 指標の一覧で、開始時から変わらず前年比も0の指標は、現在値だけを書く(1ターン目のユーザー
     メッセージが約2,350→約1,450文字)。書式も「(開始, 前年比)」に短縮。
   - 影響の件数のルール、大きさの目安、相乗・混乱の説明、ベビーシッターの例は、実測で守られ方を確認して
     あるので、文面を変えていない。
3. README・設計資料(policy_evaluation.txt)も更新。

■ 実測(gpt-5.6-luna、バブル期1988〜1997年の同じ10政策を通しで進行。API10回)
                      旧(v4)          新(v5)
  入力トークン/ターン  約10,600         約7,750
  出力トークン/ターン  約1,900          約880
  うちキャッシュ入力   (未記録)         約5,550(入力の約72%)
  推論トークン/ターン  (未記録)         約235
  所要時間/ターン      約20秒           約8秒
  料金/ターン          約0.0044ドル      約0.0016ドル(約63%減)
- 1ゲーム(30ターン+史実イベントの判定)は、約0.05ドル(1ドル=150円で約8円)。無料枠の15年分は約4円。
- OpenAIの自動キャッシュが効いていた(入力の約72%が、通常の1/10の料金で処理された)。
- 挙動は保たれた。10回すべて成功し、スキーマ違反なし。
  - 初年度の相乗・混乱は0/0。
  - 政策の費用は free_cash に入り、大きさも旧と近い(年約1兆円の政策で5など)。減税は tax_revenue と国債にも入った。
  - 見出しは平均8〜12文字(最大12)で、20文字以内が守られた。
  - レポートは「背景と影響」と「諸外国の反応」あわせて約320〜440文字で、旧(約1,100〜1,600文字)より短い。
- 差異: 悪い影響の件数が10ターン合計で30→25件と少なかった(良い影響は35→36件)。
  10ターンの標本なので誤差の範囲だが、難易度がわずかに下がる可能性がある。個々の影響の大きさ・
  対象・相乗/混乱の値は、旧・新とも実行ごとにばらつく(旧と全く同じにはならない)。

■ 補足
- 開発者向けの表示を見るには、.env に DEV_MODE=1 を書く。公開時は空欄にする。
- requirements.txt に google-genai・anthropic が残っている(アプリからは使っていない)。
- クリア条件は、旧い出力(レポート形式・財源導入前)で調整したもの。悪い影響が少ない場合の難易度は再確認が必要。
- 公開・課金の制御(無料は1人1ゲーム15年まで、以降は100円〜)は未実装。
