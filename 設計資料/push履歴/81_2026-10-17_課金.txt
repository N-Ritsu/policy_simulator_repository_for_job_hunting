81 課金(回数パックと戻りの時計の購入。Stripe のテストモード)
===============================================

■ 基本情報
- コミット: e9ed34f
- 日付: 2026-10-17
- メッセージ: Sell evaluation packs and rewind clocks through Stripe Checkout

■ 概要
ユーザーの依頼で、課金を入れた。Stripe の決済ページ(Checkout)で、買い切りの回数パックと戻りの時計を売る。
値段はユーザーが決めた(評価 100回 100円・350回 300円・1500回 980円、戻りの時計 10個 50円)。
いまは Stripe のサンドボックス(テストモード)の鍵で動かしている(実際のお金は動かない)。

■ 変更内容
1. game/billing.py(新規): 売るもの(PACKS)と、Stripe とのやりとり。
   - create_checkout: 決済ページを作る(日本円、商品名と値段はコードから渡す。戻り先のURLに checkout=success と決済の
     記号を付ける。期限は30分)。
   - fetch_session: 決済が支払い済みか・期限切れかを問い合わせる。
   - Webhook は使わない(Streamlit では受けられないため)。
2. game/storage.py: 購入の表(purchases)。決済ページを作ったときに「確認待ち」、支払いを確かめたら「支払い済み」。
   確認待ちの行を変えられたときだけ時計を足す(同じ決済で二重に足さない)。評価の回数は、支払い済みの行の合計で数える。
   期限切れは数えない。1時間に作った決済ページの数も数える(1人5つまで)。
3. app.py
   - 評価できる回数 = 無料の回数 + 買った回数 − 使った回数(remaining_evaluations)。表示は「あと○回評価できます」。
   - 購入の欄(render_shop): 4つのパックの札と「購入する」。押すと決済ページを作り、「Stripe の支払いページへ進む」
     (同じタブで開く)を出す。ログインしていなければログインの案内。
   - サイドバーのアカウントの欄に「回数を購入する」(ダイアログ)。回数を使い切ったときも「回数を購入する」。
   - 設定のページ: 残りの回数(無料・購入・使用の内訳)、戻りの時計、購入の欄、購入の履歴。
   - 支払いのあとに戻ってきたとき(settle_purchases): Stripe に問い合わせて足し、URLの印を消して、通知を出す。別の
     アカウントで戻ってきたときは、購入したアカウントでログインするよう案内する。ログインした画面を開いたときに1回、
     確認待ちの決済を確かめ直す(途中でページを閉じても取りこぼさない)。
   - 開発者モードだけ: ?testuser=1 で、Googleでログインせずにログインした人として確かめられる。
4. game/ui_theme.py: パックの値段・説明と、支払いページへのリンク(ボタンの見た目)。
5. requirements.txt に stripe を足した。README を直した。

■ 確かめたこと
- Stripe のサンドボックスの鍵で、アプリ内のブラウザ(データベースのコピーを使うサーバー。本物の記録は変えない)から、
  テスト用アカウントで「評価 100回」の決済ページを作り、Stripe の公開しているテスト用のカード番号で支払った。
  支払い済みになり(Stripe 側で complete・paid)、アプリを開き直したときに確認待ちの決済が確かめられて、評価できる回数が
  15回から115回になった。
- 支払い済みの決済の記号を付けた戻りのURLを開いても、回数は115回のまま(二重に足さない)で、URLの印が消えることを確認した。
  購入をやめた場合の戻り(checkout=cancel)でも、URLの印が消えることを確認した。
- 確認用のスクリプトで、時計のパックを支払い済みにすると時計が10個増えること、同じ決済をもう一度確かめても増えないこと、
  別のアカウントでは受け取れないこと、期限切れの決済は数えないことを確認した。
- 確かめる中で、次を直した:
  - 今の Stripe の API では、支払い方法をコードで指定できない(payment_method_types)。ダッシュボードで選ぶ形にした。
  - Stripe のライブラリの返す値は辞書ではない(.get が使えない)。to_dict() で読むようにした。
  - 通知のアイコンは絵文字だけ使える(「◆」は使えない)。
  - st.context.url には ? 以降が含まれないので、戻り先のURLの印は st.query_params から付け直した。
- 2回目の支払い(時計のパック)は、アプリ内のブラウザの操作が Stripe のカード欄に入らなくなり、画面では確かめていない
  (同じ処理なので、上のスクリプトで確かめた)。サーバーのエラーはなかった。

■ 補足・課題
- 本番(実際にお金を受け取る)の前に: Stripe の本番の審査(本人確認・口座・事業の情報)、本番の鍵(sk_live_)への
  差し替え、特定商取引法に基づく表記・利用規約・プライバシーポリシーのページ、公開用のサーバーとクラウドの
  データベース。
- 支払い方法は、Stripe のダッシュボードの「設定 → 支払い方法」で選ぶ。少額のパックがあるので、コンビニ払いなどは
  切っておくのがよい。
- 戻りの時計の説明の「有料プランで手に入るようになる予定」を、購入の場所の案内に替えた。
