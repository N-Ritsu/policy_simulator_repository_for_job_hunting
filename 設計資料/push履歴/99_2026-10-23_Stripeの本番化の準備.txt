99 Stripe の本番化の準備(テストのときの決済を片づける)
===============================================

■ 基本情報
- コミット: fce92f6
- 日付: 2026-10-23
- メッセージ: Expire pending checkouts from the other Stripe mode

■ 概要
ユーザーの依頼: Stripe の本番化をしたい。
本番化の大部分は Stripe のダッシュボードと Cloud の Secrets での作業(アカウントの有効化・本番の鍵の発行と差し替え)で、
ユーザーが行う。その前に、コードで1つ直す必要があった:
テストの鍵で作り、払わずに閉じた決済(cs_test_...)が「確認待ち」のまま公開先のデータベースに残っている。本番の鍵
(sk_live_...)では、テストの決済は問い合わせられない(Stripe が「その決済はない」と返す)。そのため、その人がログインする
たびに「支払いを確認できませんでした」と出続ける。

■ 変更内容
1. game/billing.py: same_mode(鍵と決済が同じモードか。鍵は sk_/rk_ の _test_ か _live_、決済は cs_test_ か cs_live_)。
2. app.py(_settle_purchase): 鍵と違うモードの決済は、Stripe に問い合わせずに期限切れにする。
3. README・判断の記録/05 を直した。

■ 検討した案と判断
【比べた案】 - コードで、モードの違う決済を期限切れにする / - 切り替える前に、Neon の確認待ちの行を手で消す / - 何もしない
【決め手】 手で消すと、公開先のデータベースを直接いじることになり、消し忘れや消しすぎのおそれがある。コードなら、あとで
          テストに戻したときも同じように動く。期限切れにした決済も、支払い済みにできる行(確認待ち・期限切れ)のまま
          なので、取りこぼさない。
【決めた人】 Claude(ユーザーの依頼を受けて)。

【鍵の種類】
【比べた案】 - ふつうの秘密の鍵(sk_live_) / - 権限を絞った鍵(rk_live_。決済ページの作成と確認だけ)
【決め手】 権限を絞った鍵の方が、漏れたときの被害が小さい。ただし、必要な権限が足りないと購入が動かなくなるので、
          まずはふつうの鍵で本番化し、絞った鍵は希望があれば試す、とユーザーに案内した。コードはどちらでも動く。

【支払い方法】
【決め手】 コンビニ払い・銀行振込のように、あとで支払いが済む方法は、支払いページを閉じたあとに支払われる。このアプリは
          Webhook を使わないので、反映は次にログインしたときになる。分かりにくいので、本番ではカード(と Apple Pay・
          Google Pay)だけにするよう案内した。

■ 確かめたこと
- same_mode の6通り(sk_test/sk_live/rk_test/rk_live と cs_test/cs_live の組み合わせ)を確かめた。
- 一時的な SQLite で、テストの確認待ちの決済を作り、本番の鍵のときに期限切れになり、確認待ちの一覧から消えることを確かめた。
- Stripe の API は呼んでいない(本番の鍵はまだない)。
